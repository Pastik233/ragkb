# Docker 镜像分层与构建优化

镜像由一系列只读层组成，每条 Dockerfile 指令产生一层。容器启动时在最上面加一个可写层，所有修改都写在这一层，删除文件只是加一个 whiteout 标记，底层数据仍然存在。

构建缓存按层命中：只要某一层的指令和输入没变，就直接复用缓存。所以指令顺序很关键，应该把变化频率低的放前面。典型错误是先 COPY . 再 RUN npm install，导致改一行代码就重新安装依赖。正确顺序是先 COPY package.json 和 lock 文件，执行安装，再 COPY 源码。

多阶段构建能把编译环境和运行环境分开。第一阶段用完整的 SDK 镜像编译，第二阶段只把产物复制到精简的运行时镜像里。Java 项目用 jlink 或 distroless 基础镜像，最终镜像可以从 600 MB 降到 100 MB 以内。

RUN 指令里用 && 串联多条命令并及时清理缓存文件，因为同一层里删除的文件不会减小镜像体积，只有跨层才会。

镜像标签不要用 latest，它在不同时间指向不同内容，无法复现构建。生产环境应该用内容摘要 digest 固定版本。

容器内的时区、字符集、JVM 堆参数都要显式设置。JDK 容器默认可能读不到宿主机的时区，日志时间会差 8 小时。
