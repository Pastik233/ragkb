# 缓存穿透、击穿与雪崩

缓存穿透指查询一个数据库里也不存在的 key，请求每次都绕过缓存打到数据库。常见解法是布隆过滤器：启动时把所有存在的 key 放进位数组，查询前先判断，一定不存在的直接返回。布隆过滤器有假阳性没有假阴性，所以不会漏掉真实存在的 key。另一种解法是缓存空值，把 null 也写进缓存并设置较短的过期时间，比如 60 秒。

缓存击穿指某个热点 key 突然过期，大量并发请求同时打到数据库。解法一是互斥锁：只允许一个线程去查库并重建缓存，其他线程自旋等待。解法二是逻辑过期：value 里存一个过期时间字段，物理上不设 TTL，发现逻辑过期后异步重建，期间所有请求都返回旧值。逻辑过期的可用性更好，代价是短时间内数据不一致。

缓存雪崩指大量 key 在同一时刻集中过期，或者 Redis 整体宕机。针对集中过期，可以在基础 TTL 上叠加一个随机偏移，比如 30 分钟加减 5 分钟，把过期时间打散。针对实例宕机，需要做集群和高可用，并且在应用层加本地缓存做二级兜底。

三者容易混淆，区分方法是看失效的原因：穿透是数据根本不存在，击穿是单个热点失效，雪崩是批量失效或整体不可用。

工程上还要处理缓存与数据库的一致性。常用策略是先更新数据库再删除缓存，而不是更新缓存，因为更新缓存的并发顺序难以保证。删除失败可以用消息队列重试，或者订阅数据库 binlog 异步删除，把不一致窗口压到毫秒级。
