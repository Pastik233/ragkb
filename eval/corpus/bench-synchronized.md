# synchronized 的锁升级

synchronized 的锁状态记录在对象头的 Mark Word 里，共四种：无锁、偏向锁、轻量级锁、重量级锁，只能升级不能降级。

偏向锁针对只有一个线程反复进入的场景。第一次加锁时用 CAS 把线程 ID 写进 Mark Word，之后同一线程再进来只需比对 ID，不再有 CAS 开销。JDK 15 之后偏向锁默认关闭并被标记为废弃，因为它在高并发下撤销成本很高，收益不如预期。

轻量级锁用于线程交替执行的场景。线程在自己的栈帧里建 Lock Record，用 CAS 把 Mark Word 指向它。如果 CAS 失败说明有竞争，就膨胀为重量级锁。

重量级锁依赖操作系统的互斥量，未抢到锁的线程进入阻塞状态，涉及用户态和内核态切换，开销最大。但它的好处是阻塞不占 CPU。

锁只能升级不能降级，这是为了权衡：升级容易、降级需要安全点，实现复杂且收益有限。

实际优化手段包括锁消除（JIT 发现对象不会逃逸，直接去掉同步）、锁粗化（把相邻的多次加锁合并成一次）。代码层面应该减小锁粒度，比如用 ConcurrentHashMap 的分段思路，或者只锁必要的临界区。
