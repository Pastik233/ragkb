# Spring 事务传播行为

REQUIRED 是默认值。如果当前存在事务就加入，没有就新建一个。绝大多数业务方法用这个，因为它保证多次调用共享同一个事务，一起提交或一起回滚。

REQUIRES_NEW 会挂起当前事务，另起一个独立事务。典型场景是记录操作日志：主业务回滚了，日志仍然要留下。注意挂起不是免费的，它会占用额外的数据库连接，嵌套层数多了容易把连接池耗尽。

NESTED 使用数据库保存点实现，本质还是同一个物理事务。内层失败可以只回滚到保存点，外层可以选择继续提交。它依赖 JDBC 的 Savepoint 支持，而且只对 DataSourceTransactionManager 有效，JTA 环境下不成立。

SUPPORTS 表示有事务就加入，没有也能执行，适合纯查询方法。NOT_SUPPORTED 会挂起事务以非事务方式执行。MANDATORY 要求必须已有事务，否则抛异常。NEVER 要求必须没有事务，否则抛异常。

最常见的失效场景是自调用。在同一个类里用 this 调用另一个带 `@Transactional` 的方法，注解不会生效，因为事务是基于代理实现的，自调用绕过了代理对象。解决办法是把方法拆到另一个 Bean，或者注入自己的代理，或者用 AopContext.currentProxy。

另一个高频坑是异常类型。默认只对 RuntimeException 和 Error 回滚，受检异常不会触发回滚。需要显式写 `@Transactional(rollbackFor = Exception.class)`。

还有事务里做远程调用的问题。事务开启期间一直占着数据库连接，如果中间调用了耗时几秒的 HTTP 接口，连接就被白白占用。正确做法是把远程调用移到事务外面，只在事务内做数据库写入。
