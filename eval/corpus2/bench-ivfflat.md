# IVFFlat 索引的工作方式

IVFFlat 是 pgvector 提供的另一种近似最近邻索引，思路和 HNSW 完全不同。它先用 k-means 把所有向量聚成 lists 个簇，每个簇有一个中心点，查询时先找距离最近的 nprobe 个簇，只在这些簇内部做精确比较。

lists 参数建议按行数估算：行数小于一百万时取行数除以 1000，大于一百万时取行数的平方根。nprobe 是查询时探测的簇数，默认 1，调大能提高召回率但线性增加延迟。

IVFFlat 必须在有数据之后建索引，因为聚类需要样本。官方建议先插入一部分代表性数据再建索引，否则簇的划分会失真。后续大量插入会让分布偏移，需要重建索引。

和 HNSW 相比，IVFFlat 建索引更快、内存占用更低，但召回率和查询延迟的权衡不如 HNSW 平滑。HNSW 的图结构在增量插入时表现更稳定，而 IVFFlat 在数据分布变化后性能会下降。

如果数据量不大、写入频繁，HNSW 更省心。如果是离线批量导入、数据静态，IVFFlat 建索引的时间和内存优势就体现出来了。

两者都要求查询向量和索引的 operator class 匹配，也都要 ORDER BY 加 LIMIT 才会走索引。
