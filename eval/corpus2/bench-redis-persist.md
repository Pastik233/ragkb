# Redis 的持久化方式

RDB 是快照持久化，按配置的时间间隔把内存数据 fork 子进程写成二进制文件。恢复速度快，文件紧凑，适合做备份和灾备。缺点是两次快照之间的数据会丢，fork 时如果内存很大，复制页表本身也会造成明显停顿。

AOF 是追加写日志，把每条写命令追加到文件末尾。同步策略有三种：always 每条都刷盘，最安全但性能最差；everysec 每秒刷一次，最多丢一秒数据，是默认值；no 交给操作系统决定。

AOF 文件会不断膨胀，需要重写。重写不是读旧文件，而是根据当前内存状态生成一份最小命令集，同样通过 fork 子进程完成。Redis 4.0 之后支持混合持久化，重写时把当前状态写成 RDB 格式放在文件头，后续增量命令以 AOF 格式追加，兼顾恢复速度和数据完整性。

生产环境一般两个都开。RDB 用于定期备份和快速恢复，AOF 用于保证数据完整。如果只做缓存、能接受丢失，可以只开 RDB 或者都关掉。

需要注意，Redis 的持久化不等于高可用。主从复制是异步的，主节点挂掉时未同步的写会丢。要真正保证不丢，需要配合 WAIT 命令或者使用 Redis 的事务与确认机制，代价是延迟上升。
