# Spring AOP 的代理方式

Spring AOP 基于动态代理，运行时生成代理对象包裹目标对象。两种实现：JDK 动态代理要求目标类实现接口，通过反射生成实现同一接口的代理类；CGLIB 通过继承生成子类，用字节码增强覆盖方法。

Spring Boot 2.0 之后默认使用 CGLIB，因为它在目标类没有接口时也能工作，而且不需要强制面向接口编程。可以通过 `spring.aop.proxy-target-class=false` 切回 JDK 代理。

CGLIB 的限制是被代理的方法不能是 final 或 private，因为子类无法覆盖。JDK 代理的限制是只能代理接口中声明的方法，实现类的额外方法不可见。

代理只在通过容器获取 Bean 时生效。如果方法在同一个类内部自调用，走的是 this 引用，完全绕过了代理，所以事务、缓存、异步这些基于 AOP 的注解都会失效。这是排查“注解不生效”时第一个要排除的原因。

通知类型有五种：Before、After、AfterReturning、AfterThrowing、Around。Around 最灵活，可以控制是否执行目标方法、修改返回值，也是事务实现用的类型。

多个切面的顺序用 `@Order` 控制，数值越小越靠外层。事务切面通常应该在最外层，保证缓存、日志这些切面在事务边界内执行。
