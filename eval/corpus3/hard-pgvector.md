# pgvector 索引的实践细节

## HNSW 的三个参数

m 控制每个节点在图中保留的双向连接数，默认 16。它决定了图的连通性：m 越大，每个节点能探索的邻居越多，召回率越高，但索引体积和插入时的维护成本也线性上升。一般 16 到 32 之间够用，超过 64 收益很小。

ef_construction 是建索引时的动态候选列表长度，默认 64。它影响图的质量：值越大，建索引时考虑的候选越多，图结构越好，但建索引越慢。它是建索引阶段的参数，索引建好之后改它没有意义。

ef_search 是查询时的候选列表长度，默认 40，可以在会话里用 `SET hnsw.ef_search = 100` 调整。它不改变索引结构，只影响单次查询探索的广度，是运行时唯一需要调的旋钮。调大召回上升、延迟上升，调小反之。

## 与 IVFFlat 的选择

IVFFlat 靠聚类划分，必须先有数据再建索引，lists 决定簇的数量，nprobe 决定查询时探测几个簇。数据分布变化后需要重建索引。HNSW 支持增量插入，图结构在持续写入时更稳定，代价是内存占用更高。

数据量小、写入频繁选 HNSW；数据静态、批量导入选 IVFFlat 更省资源。

## 查询写法的影响

索引只对带 ORDER BY 和 LIMIT 的查询生效，而且 ORDER BY 里必须写完整的距离表达式，不能引用 SELECT 的别名，否则优化器识别不到索引。距离算子必须和 operator class 匹配：余弦用 `<=>` 配 vector_cosine_ops，欧氏用 `<->` 配 vector_l2_ops，内积用 `<#>` 配 vector_ip_ops。

带 WHERE 过滤时，HNSW 先取近似结果再过滤，可能凑不满 LIMIT。pgvector 0.8 之后可以用迭代扫描缓解。
