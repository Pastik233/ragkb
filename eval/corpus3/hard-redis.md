# 缓存问题的处理细节

## 穿透与布隆过滤器

穿透的本质是请求的 key 在数据库里也不存在，缓存永远不命中。布隆过滤器用一个位数组加多个哈希函数来判断元素是否存在，它的特点是判断“不存在”一定准确，判断“存在”可能有假阳性。所以它能挡住不存在的请求，但放过的请求仍要回源。

布隆过滤器不支持删除，元素只能加不能减。如果数据会删除，需要用计数布隆或者定期重建。另一种更简单的做法是缓存空值，把 null 也写进去并设置较短的 TTL，比如 60 秒，但要防止大量不同的随机 key 把缓存撑爆。

## 击穿与互斥重建

击穿是单个热点 key 失效瞬间，大量请求同时回源。互斥重建的做法是只让一个线程去查库，其他线程等待，拿到结果后一起返回。实现上用 Redis 的 setnx 加过期时间，注意锁要设超时并且只由持有者删除。

逻辑过期是另一种思路：value 里存一个逻辑过期时间字段，物理上不设 TTL。发现逻辑过期后，一个线程异步重建，其他请求直接返回旧值。它的可用性更好，代价是短时间内读到旧数据。

## 雪崩与 TTL 打散

雪崩有两个来源：大量 key 同时过期，或者缓存实例整体不可用。前者靠给 TTL 加随机偏移解决，比如 30 分钟加减 5 分钟，把过期时间摊开。后者要靠高可用架构，加本地缓存做二级兜底，并在缓存不可用时用限流保护数据库。

## 一致性策略

常用的是先更新数据库再删除缓存，而不是更新缓存。原因是并发更新缓存的顺序无法保证，可能旧值覆盖新值。删除失败的补偿可以走消息队列重试，或者订阅 binlog 异步删除。
