# 消息队列怎么选

## Kafka

Kafka 的高吞吐靠两件事：顺序写磁盘和零拷贝。消息追加到分区文件末尾，是纯顺序 IO，磁盘顺序写的速度接近内存。消费时通过 sendfile 把数据从页缓存直接送到网卡，跳过用户态拷贝。

它天生适合日志采集、埋点、流式处理这类量大但业务语义弱的场景。单机吞吐可以到十万级以上。

缺点是功能相对朴素：延迟消息、事务消息要靠外部方案或者较新版本的特性，消息路由只有 topic 和分区两层。

## RocketMQ

RocketMQ 由阿里开源，针对电商场景做了很多增强：事务消息用半消息加回查实现最终一致，延迟消息支持固定档位，消息可以按 tag 过滤。

它的单机吞吐在十万级，比 Kafka 略低，但功能完整度高，适合订单、支付这类需要事务保证的业务。

## RabbitMQ

RabbitMQ 基于 AMQP 协议，核心优势是交换机支持灵活路由：直连、主题、扇出、头匹配四种模式，可以把一条消息按规则分发到多个队列。

它的单机吞吐在万级，明显低于前两者，但延迟低、管理界面完善，适合业务解耦和任务分发这类消息量不大但路由复杂的场景。

## 选型维度

先看吞吐量级，十万级以上基本只能选 Kafka 或 RocketMQ。再看是否需要事务消息、延迟消息。最后看团队运维能力，Kafka 依赖 ZooKeeper 或 KRaft，RocketMQ 依赖 NameServer，RabbitMQ 的集群模式对网络分区比较敏感。
