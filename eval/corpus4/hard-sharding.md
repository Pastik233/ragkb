# 分库分表的落地细节

## 垂直与水平

垂直拆分按业务边界切，把不同领域的表分到不同库，比如订单库、用户库、商品库。它解决的是单库表太多、职责混乱的问题，不解决单表数据量大的问题。

水平拆分把同一张表的数据按规则分到多个库或表。只有单表行数到了千万级、索引已经优化到极限时才考虑，因为分片会带来跨库查询、分布式事务、全局 ID 这一整套复杂度。

## 分片键

分片键决定数据怎么分布，一旦选定很难改。选错分片键会导致数据倾斜，比如按用户 ID 分片但某些大客户的数据量是普通用户的上万倍。

常见路由方式有三种：取模最简单但扩容麻烦；范围分片利于范围查询但容易热点；一致性哈希在扩容时只影响相邻节点，迁移量小。

取模扩容要把大部分数据重新分布，双倍扩容只迁移一半，因为原来 N 个库扩到 2N 个库时，每个库的数据只需要判断是否要搬到对应的新库。

## 跨库查询

跨库 join 只能由应用层拼装：先查主表拿到分片键列表，再按分片键去各库查从表，最后在内存里组装。这会带来 N+1 查询问题，通常要配合冗余字段或者宽表来规避。

跨库分页更麻烦，因为无法用单个库的 limit offset，需要各库取足够多的数据再归并排序。

## 全局 ID

雪花算法是常见方案：41 位时间戳加 10 位机器 ID 加 12 位序列号，单机每毫秒可生成 4096 个不重复 ID。它依赖机器时钟，时钟回拨会导致 ID 重复，需要额外处理。
