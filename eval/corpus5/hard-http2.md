# HTTP/2 与 HTTP/3

HTTP/1.1 的核心问题是队头阻塞：同一个 TCP 连接上请求必须串行，前一个响应没回来，后面的只能等。浏览器靠开 6 个并发连接缓解，但连接本身有握手和慢启动成本。

HTTP/2 引入二进制分帧和多路复用，把请求拆成带 stream id 的帧，同一个连接上可以交错传输多个请求，彻底解决了应用层的队头阻塞。它还支持头部压缩 HPACK 和服务端推送。

但 HTTP/2 仍然受 TCP 层队头阻塞影响：一个 TCP 包丢失，内核要等重传，这条连接上所有 stream 都被卡住。丢包率高的网络下 HTTP/2 反而不如 HTTP/1.1 的多连接。

HTTP/3 把传输层换成 QUIC，基于 UDP 实现可靠传输，流与流之间独立重传，一个流丢包不影响其他流。QUIC 还把 TLS 1.3 握手合并进连接建立，首次连接 1-RTT，恢复连接可以做到 0-RTT。

代价是 UDP 在部分网络里被限速或阻断，需要回退机制。另外 0-RTT 有重放攻击风险，只适合幂等请求。

实际部署上，HTTP/2 需要 HTTPS，浏览器不再支持明文 h2c；HTTP/3 需要 ALPN 协商，通常通过 Alt-Svc 头告知客户端。
