# 链路追踪与日志规范

分布式系统排查问题靠 traceId 把一次请求在所有服务里的日志串起来。入口生成 traceId，通过 HTTP 头或消息属性透传，每个服务的日志格式里都带上它。

MDC 是 logback 提供的线程上下文，把 traceId 放进去后，日志模板里用 %X{traceId} 就能自动输出。注意线程池场景要手动传递：提交任务时把 MDC 内容复制过去，否则子线程拿不到。

OpenTelemetry 统一了 trace、metric、log 三者的采集协议，traceId 在三个信号之间共享。它的上下文传播基于 W3C Trace Context 规范，用 traceparent 头传递。

Span 是一次操作的记录，有开始时间、结束时间和父子关系。一次请求的 span 组成一棵树，能看出每一层的耗时。采样率通常设 1% 到 10%，全量采集的存储成本很高。

日志级别要克制：debug 只在排查时开，info 记录关键业务节点，warn 表示可恢复的异常，error 表示需要人介入。把异常堆栈打全，但不要在每个 catch 里都打一遍，会重复几十次。

日志要结构化，用 JSON 而不是拼接字符串，方便后续用 ELK 或 Loki 检索。敏感字段脱敏要在入库前做，事后清理成本极高。
