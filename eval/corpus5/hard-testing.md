# 测试分层与工具选择

测试金字塔分三层：底层是单元测试，数量最多、运行最快；中间是集成测试，验证模块之间的协作；顶层是端到端测试，数量最少、最脆弱。

单元测试要隔离外部依赖，用 Mockito 打桩。原则是只测行为不测实现，避免为了覆盖率去断言私有方法的调用次数，那样重构就会失败。

集成测试跑真实数据库，Testcontainers 启动一个临时 PostgreSQL 容器，测试结束后销毁，比 H2 更接近生产行为。H2 的 SQL 方言和索引行为和真实库差异很大，容易掩盖问题。

Spring Boot 的 @SpringBootTest 会加载完整上下文，速度慢。只测 Web 层可以用 @WebMvcTest，只加载 MVC 相关组件；只测数据层用 @DataJdbcTest。按需选择能显著缩短反馈时间。

测试数据要独立，每个测试自己准备和清理，不要依赖执行顺序。@Transactional 加在测试方法上可以自动回滚，但对需要提交的场景不适用。

覆盖率不是目标，60% 到 80% 的核心路径覆盖比 100% 的无效断言有价值。重点覆盖边界条件、空值、并发和异常分支。
